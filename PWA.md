# Orbit as a PWA

How to install Orbit straight from the browser, what it does offline, and how the pieces are wired.

This is the no-APK route. For packaging a signed Android APK and hosting on Vercel, see [DEPLOY.md](DEPLOY.md).

---

## 1. Installing

Orbit must be served over **HTTPS** to be installable (`localhost` is exempt, so local testing works).

### Android — Chrome
Menu (⋮) → **Add to Home screen** / **Install app**. Chrome usually shows an install prompt on its own after a visit or two.

Launches standalone: no address bar, its own entry in the app switcher, own icon.

### iOS / iPadOS — Safari
Share (□↑) → **Add to Home Screen**.

Two Safari-only caveats:
- **It must be Safari.** Chrome and Firefox on iOS can't install PWAs — the option won't appear.
- **Data is per-installation.** Removing the icon deletes the IndexedDB behind it. Sign in to Cloud Sync ([DEPLOY.md §9](DEPLOY.md)) if you want that data to survive.

### Desktop — Chrome / Edge
Install icon (⊕) in the address bar, or Menu → **Cast, save and share → Install page as app**.

Opens in its own window. The layout is centred at `max-w-2xl` rather than stretched, so it reads like an app rather than a wide web page.

## 2. What works offline

**After one online visit to `/projects`, the whole app works with no network.** Projects, dashboard, settings, creating and editing — all of it.

That works because your data was never on a server to begin with: it lives in IndexedDB on the device. The service worker only needs to cache the app shell around it.

What gets cached on that first visit:

| Cached | How |
|---|---|
| The three route documents | Precached at install, then refreshed network-first |
| Every JS/CSS chunk | Scraped from the HTML at install, plus cache-first at runtime |
| Inter (the font) | Self-hosted under `/_next/static/media`, so it's covered by the same rule |
| Icons, manifest, brand assets | Precached at install |

`/dashboard` and `/settings` warm up for free — the App Router prefetches in-viewport `<Link>`s, and the bottom nav renders all three.

**If you go offline before that first visit finishes**, you get a small built-in offline page with a retry button. It's a self-contained HTML string inside the worker rather than a real route, because a real page would need its own JS chunks — which by definition aren't cached in the one situation that can reach it.

### Verifying it yourself

```bash
npm run build && npm start
```

Load `/projects` once, then DevTools → Network → **Offline** → hard reload. The app should render normally, not the offline page. Tap through all three tabs.

The service worker **only registers in production builds**. In dev it actively unregisters itself and clears its caches, so it can never serve stale chunks over hot reload.

## 3. Startup splash

Three separate mechanisms, deliberately matched so the handoff between them is invisible — same `#0F172A` field, same centred mark:

| Where | What |
|---|---|
| **iOS** | 13 pre-rendered launch images, one per device, via `apple-touch-startup-image` |
| **Android** | Generated by the system from `background_color` + the 512px manifest icon |
| **In-app** | A React overlay shown while IndexedDB loads, on every platform |

The in-app splash clears as soon as the first read settles, with a 700ms floor so it can't flash and a 3s cap so a stalled database can't trap you behind it. It's a fixed overlay rendered *beside* the app, never wrapping it — if it ever misbehaved, the app underneath is still mounted.

iOS only shows a launch image when a `<link>` matches the device **exactly**, which is why it's a lookup table rather than one scaled image. A device not in the table gets a plain background — see [DEPLOY.md §1](DEPLOY.md) for adding one.

## 4. How it's wired

| Piece | File |
|---|---|
| Manifest | [`public/manifest.json`](public/manifest.json) |
| Service worker | [`public/sw.js`](public/sw.js) |
| Registration | [`components/layout/AppShell.tsx`](components/layout/AppShell.tsx) — production only |
| Icons + splash generators | [`scripts/generate-icons.mjs`](scripts/generate-icons.mjs), [`scripts/generate-splash.mjs`](scripts/generate-splash.mjs) |
| iOS device table | [`lib/pwa/splash-screens.ts`](lib/pwa/splash-screens.ts) |
| Metadata / viewport | [`app/layout.tsx`](app/layout.tsx) |
| In-app splash | [`components/layout/SplashScreen.tsx`](components/layout/SplashScreen.tsx) |

Regenerate all image assets with `npm run assets` after editing `public/icons/icon.svg` or `icon-mark.svg`.

### Service worker strategy

| Request | Strategy |
|---|---|
| `/_next/static/*` | **cache-first** — Turbopack content-hashes filenames, so a URL's bytes never change |
| Navigations | network-first, cache fallback, keyed on pathname only |
| RSC payloads | network-first only |
| Other same-origin GETs | cache-first |
| `/_next/image`, HMR, `/sw.js` | never intercepted |

Two non-obvious details, both of which cause silent breakage if you touch this file:

- **Cache lookups use `ignoreVary: true`.** Next sends `Vary: rsc, next-router-state-tree, …` on every app-router response, and the Cache API honours `Vary` — a plain `match()` misses everything you stored.
- **Navigations are keyed on pathname only.** Otherwise the manifest's own `/projects?action=add` shortcut misses the cached `/projects` document when offline.

Bump `VERSION` in `sw.js` whenever you change caching behaviour. The `activate` handler purges every cache that isn't the current version, so old ones can't linger.

### Icons

`npm run icons` produces nine "any" sizes (72–1024), three maskable variants, and a flattened 180px Apple touch icon.

Maskable is a **separate** image, not a copy: Android only guarantees the central 66% of an adaptive icon is visible, and the standard mark fills 73.5% of its canvas — the satellite nodes would be clipped. The maskable variant scales the mark to 82% on a full-bleed field, landing at 60.3%. The generator **fails** if that ever drifts past the limit.

## 5. Updates

Web changes reach installed PWAs on their own — the app loads your live site, so a deploy is picked up on next launch. No reinstall.

If you changed caching rules, bump `VERSION` in `sw.js` so old caches are purged.

Installed **APKs** are different: name, package id, icon, `theme_color`, `start_url`, display mode and orientation are baked in at package time and need a rebuild. See [DEPLOY.md §7](DEPLOY.md).

## 6. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| No install prompt | Not HTTPS, manifest failing to load, or already installed. Check DevTools → Application → Manifest. |
| Blank screen offline | The first visit must complete online. Confirm `orbit-static-v3` holds `/_next/static/…` entries under Application → Cache Storage. |
| Stale content after deploy | Bump `VERSION` in `sw.js`. To force a reset: Application → Service Workers → **Unregister**, then Application → **Clear storage**. |
| Icon not updating | Android caches launcher icons hard. Uninstall and reinstall. |
| Plain white iOS splash | That device isn't in `APPLE_SPLASH_SCREENS`. |
| Content under the notch / home bar | `viewportFit: 'cover'` in `app/layout.tsx` plus `env(safe-area-inset-*)` — real devices only, headless browsers report 0. |
| Works in dev, not installed | The service worker doesn't register in dev by design. Always test with `npm run build && npm start`. |

> **Careful with "Clear storage"** — it wipes IndexedDB too, which is your projects. To reset only the worker, use the console:
> ```js
> navigator.serviceWorker.getRegistrations().then(r => r.forEach(x => x.unregister()));
> caches.keys().then(k => k.forEach(c => caches.delete(c)));
> ```

### Auditing

DevTools → Lighthouse → **Progressive Web App**. Expect passes on installability, a valid manifest, a maskable icon, `theme-color`, and offline capability.

Application panel is the faster read: **Manifest** (icons resolve, no 404s), **Service Workers** (activated and running), **Cache Storage** (`orbit-static-v3` + `orbit-runtime-v3`).
